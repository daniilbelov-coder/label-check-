# 🧪 Инструкция по тестированию защиты от Race Conditions

## Быстрая проверка функциональности ETag

### 1. Автоматический тест

```bash
# Создайте тестовый файл
cat > test-etag.js << 'EOF'
import { getPromptsETag, getPromptsMetadata } from './services/prompts.js';

console.log('=== Тест функций ETag ===\n');

const etag1 = getPromptsETag();
console.log('1. ETag:', etag1);
console.log('   Формат MD5:', /^[a-f0-9]{32}$/.test(etag1) ? '✅ OK' : '❌ FAIL');

const metadata = getPromptsMetadata();
console.log('\n2. Метаданные:', {
  etag: metadata.etag,
  keys: Object.keys(metadata.prompts)
});

const etag2 = getPromptsETag();
console.log('\n3. Стабильность:', etag1 === etag2 ? '✅ OK' : '❌ FAIL');

console.log('\n=== Тест завершен ===');
EOF

# Запустите тест
node test-etag.js

# Удалите тестовый файл
rm test-etag.js
```

## Тестирование конфликта в браузере

### Шаг 1: Запустите локальный сервер

```bash
npm run dev
```

Откройте http://localhost:3000

### Шаг 2: Войдите в систему

1. Нажмите кнопку входа
2. Введите пароль: `label2025`
3. Нажмите "Войти"

### Шаг 3: Симуляция конфликта

1. **Откройте настройки в двух браузерах:**
   - Браузер 1: Chrome (http://localhost:3000)
   - Браузер 2: Firefox или Safari (http://localhost:3000)
   - Или используйте обычный режим + инкогнито в одном браузере

2. **В обоих браузерах:**
   - Нажмите кнопку "Настройки" (⚙️ иконка)
   - Дождитесь загрузки промптов

3. **Браузер 1:**
   - Перейдите на вкладку "Фуд"
   - Добавьте строку в конец промпта: `\n\nТестовое изменение от Браузера 1`
   - Нажмите "Сохранить"
   - ✅ Должно показать "Промпты успешно сохранены"

4. **Браузер 2:**
   - Перейдите на вкладку "Нон-фуд"
   - Добавьте строку в конец промпта: `\n\nТестовое изменение от Браузера 2`
   - Нажмите "Сохранить"
   - ⚠️ **Должно показать модальное окно "Конфликт изменений"**

### Ожидаемый результат

**Модальное окно должно содержать:**
- 🟠 Иконка предупреждения
- Заголовок: "Конфликт изменений"
- Текст: "Промпты были изменены другим пользователем во время вашего редактирования"
- Кнопка: "Обновить и начать заново"
- Кнопка: "Отмена"

**После нажатия "Обновить и начать заново":**
- Промпты перезагружаются с сервера
- Показываются изменения из Браузера 1
- Изменения из Браузера 2 НЕ сохранены (как и ожидалось)

## Тестирование через curl

### Получить текущий ETag

```bash
curl -i http://localhost:3000/api/prompts \
  -H "X-API-Key: dev-secret-change-me"
```

**Ожидаемый ответ:**

```
HTTP/1.1 200 OK
ETag: 4765b8614fce1f619f7b47ed8c60aebc
Content-Type: application/json

{
  "prompts": {...},
  "etag": "4765b8614fce1f619f7b47ed8c60aebc",
  "lastModified": "2026-02-05T11:43:34.132Z"
}
```

### Сохранить с правильным ETag (успех)

```bash
curl -X POST http://localhost:3000/api/prompts \
  -H "X-API-Key: dev-secret-change-me" \
  -H "Content-Type: application/json" \
  -d '{
    "prompts": {
      "food": "test",
      "nonfood": "test",
      "inter": "test",
      "ge": "test"
    },
    "etag": "4765b8614fce1f619f7b47ed8c60aebc"
  }'
```

**Ожидаемый ответ:**

```json
{
  "success": true,
  "message": "Промпты успешно обновлены",
  "etag": "новый-etag",
  "lastModified": "2026-02-05T12:00:00.000Z"
}
```

### Сохранить с неправильным ETag (конфликт)

```bash
curl -X POST http://localhost:3000/api/prompts \
  -H "X-API-Key: dev-secret-change-me" \
  -H "Content-Type: application/json" \
  -d '{
    "prompts": {
      "food": "test",
      "nonfood": "test",
      "inter": "test",
      "ge": "test"
    },
    "etag": "wrong-etag-12345"
  }'
```

**Ожидаемый ответ:**

```
HTTP/1.1 409 Conflict
```

```json
{
  "error": "Конфликт: Промпты были изменены другим пользователем",
  "message": "Пожалуйста, обновите страницу и повторите редактирование",
  "currentETag": "текущий-etag",
  "currentPrompts": {...},
  "lastModified": "2026-02-05T12:00:00.000Z"
}
```

## Проверка на Railway

Если приложение развернуто на Railway:

1. Замените `http://localhost:3000` на URL вашего Railway приложения
2. Замените `dev-secret-change-me` на значение переменной `API_SECRET` из Railway
3. Повторите тесты выше

**Важно:** В production режиме (NODE_ENV=production) проверка API ключа обязательна.

## Что делать если тест не прошел

### Модальное окно не появляется

1. Проверьте консоль браузера (F12) на наличие ошибок
2. Убедитесь, что сервер возвращает 409 статус:
   ```javascript
   // В Network tab должен быть запрос с статусом 409
   POST /api/prompts -> 409 Conflict
   ```

### ETag не меняется после сохранения

1. Проверьте, что `reloadPrompts()` вызывается после `savePrompts()`
2. Проверьте, что сервер возвращает новый ETag в ответе

### Всегда возникает конфликт (даже без конкурентного редактирования)

1. Проверьте, что ETag правильно сохраняется в состоянии компонента
2. Проверьте, что ETag отправляется в теле запроса (не в заголовке)
