## Что такое промпты?

Промпты — это системные инструкции для AI-модели, которые определяют, как она должна обрабатывать текст на этикетках для разных типов продукции.

**В приложении есть 4 типа промптов:**
- **food** (Фуд) — для пищевой продукции
- **nonfood** (Нон-фуд) — для непищевой продукции (косметика, бытовая химия)
- **inter** (Межнар) — для международных этикеток
- **ge** (ГЕ) — для готовых блюд (гастроемкости)

**Важно:** Промпты хранятся только на сервере и никогда не отправляются в браузер (коммерческая тайна).

## Как загружаются промпты

### При старте сервера

```
1. Сервер запускается
2. Читается файл prompts-data.json
3. Если файл существует → загружаются промпты из файла
4. Если файл НЕ существует → используются дефолтные промпты из services/prompts.js
```

**Файлы:**
- `prompts-data.json` — основной файл с промптами (не попадает в git)
- `services/prompts.js` — содержит дефолтные промпты (попадает в git)

### На клиенте (браузер)

Когда пользователь открывает страницу с настройками:
```
1. Браузер отправляет GET /api/prompts с API ключом
2. Сервер возвращает текущие промпты + ETag (версия)
3. Промпты отображаются в UI
```

## Когда промпты обновляются

### Автоматически
- **При старте сервера** — промпты загружаются из `prompts-data.json` или дефолтных значений

### Вручную
- **Через UI (Настройки)** — администратор может отредактировать промпты и нажать "Сохранить"
- **API POST /api/prompts** — можно обновить промпты программно (требуется API ключ)

### Процесс обновления через UI:
```
1. Пользователь редактирует промпт
2. Нажимает "Сохранить"
3. Браузер отправляет POST /api/prompts с новыми промптами и ETag
4. Сервер проверяет ETag (защита от конфликтов)
5. Если ETag совпадает → промпты сохраняются в prompts-data.json
6. Сервер перезагружает промпты в память
7. Новые промпты сразу используются для обработки этикеток
```

**Важно:** После сохранения промптов **не требуется рестарт сервера** — изменения применяются мгновенно.

## Когда промпты могут "слетать"

### ❌ Ситуация 1: Redeploy на Railway

**Проблема:**
- Railway использует ephemeral filesystem (временная файловая система)
- При redeploy файл `prompts-data.json` удаляется
- Сервер загружает дефолтные промпты из `services/prompts.js`

**Решение:**
- После каждого redeploy нужно **заново ввести промпты** через UI
- Либо: использовать базу данных (PostgreSQL/MongoDB) вместо файла

### ❌ Ситуация 2: Ошибка при сохранении

**Проблема:**
- Нет прав на запись в файл `prompts-data.json`
- Ошибка в формате промптов (слишком длинный промпт >100KB)

**Решение:**
- Проверить логи сервера (есть сообщение об ошибке)
- Проверить права доступа к файлу
- Убедиться, что промпт не превышает 100,000 символов

### ❌ Ситуация 3: Конфликт при одновременном редактировании

**Проблема:**
- Два пользователя одновременно редактируют промпты
- Один сохраняет → другой получает ошибку 409 Conflict

**Решение:**
- См. раздел [Защита от конфликтов](#защита-от-конфликтов-race-conditions)

## Защита от конфликтов (Race Conditions)

### Проблема

Если два пользователя одновременно редактируют промпты:
```
Время | Пользователь A           | Пользователь B           | Результат
T0    | Читает промпты v1        |                          |
T1    |                          | Читает промпты v1        |
T2    | Изменяет food → v1-A     |                          |
T3    | Сохраняет                |                          | food=v1-A
T4    |                          | Изменяет nonfood → v1-B  |
T5    |                          | Пытается сохранить       | ❌ КОНФЛИКТ!
```

### Решение: Optimistic Locking с ETag

Мы используем стандартный механизм HTTP (ETag) для защиты от конфликтов:

1. **При загрузке** промптов сервер вычисляет ETag (MD5 хеш) и отправляет клиенту
2. **При сохранении** клиент отправляет ETag обратно
3. **Сервер проверяет** ETag:
   - Если ETag совпадает → сохранение разрешено ✅
   - Если ETag НЕ совпадает → возвращается ошибка 409 Conflict ❌

### Что делать при конфликте?

**Если вы получили ошибку "Конфликт изменений":**

```
┌─────────────────────────────────────────────────┐
│ ⚠️  Конфликт изменений                          │
│                                                 │
│ Промпты были изменены другим пользователем      │
│ во время вашего редактирования.                 │
│ Ваши изменения не сохранены.                    │
│                                                 │
│ [Обновить и начать заново]  [Отмена]           │
└─────────────────────────────────────────────────┘
```

**Действия:**
1. Нажмите "Обновить и начать заново"
2. Промпты перезагрузятся с сервера (будут актуальные)
3. Внесите изменения заново
4. Сохраните

**Рекомендация:**
- Договоритесь с коллегами, кто редактирует промпты в конкретный момент
- Редактируйте промпты по очереди, а не одновременно

## Часто задаваемые вопросы (FAQ)

### Нужно ли перезапускать сервер после изменения промптов?

**Нет!** Изменения применяются автоматически после нажатия "Сохранить" в UI.

### Где хранятся промпты?

1. **На сервере:** в файле `prompts-data.json` (ephemeral на Railway)
2. **В коде:** дефолтные значения в `services/prompts.js`
3. **В браузере:** НЕ хранятся (только временно при редактировании)

### Можно ли посмотреть промпты в браузере?

**Нет.** Промпты — коммерческая тайна и доступны только через:
- API с проверкой API ключа (для админов)
- UI настроек (после авторизации)

### Что делать, если после redeploy промпты сбросились?

1. Зайти в настройки (кнопка "Настройки")
2. Ввести все 4 промпта заново (food, nonfood, inter, ge)
3. Сохранить

**Альтернатива:** Использовать базу данных вместо файла (требует изменения кода)

### Можно ли откатить изменения промптов?

**Частично.** Есть два варианта:

**Вариант 1: Откат к дефолтным промптам**
```bash
# На сервере удалить файл prompts-data.json
rm prompts-data.json

# Перезапустить сервер
# Промпты загрузятся из services/prompts.js
```

**Вариант 2: Откат через git**
```bash
# Если дефолтные промпты в services/prompts.js были обновлены
git checkout services/prompts.js
```

**Важно:** История изменений промптов НЕ сохраняется. Рекомендуется:
- Делать резервные копии промптов перед изменениями
- Хранить промпты в отдельном документе (Google Docs / Notion)

### Как проверить, какой промпт используется сейчас?

**Способ 1: Через UI**
```
1. Открыть настройки
2. Выбрать тип промпта (food / nonfood / inter / ge)
3. Посмотреть текст в поле
```

**Способ 2: Через API**
```bash
curl https://your-app.railway.app/api/prompts \
  -H "X-API-Key: <ваш_api_ключ>"
```

### Как получить API ключ?

API ключ — это пароль для входа в систему:
```
Пароль: label2025
SHA-256: <хеш пароля>
```

**Для API запросов:**
- В production: установить `API_SECRET` в environment variables Railway
- В development: используется дефолтный ключ `dev-secret-change-me`

## 🛠️ Техническая информация

### Архитектура

```
┌─────────────────┐
│   Browser       │
│  (Settings UI)  │
└────────┬────────┘
         │ GET /api/prompts (with ETag)
         │ POST /api/prompts (with ETag)
         ▼
┌─────────────────┐
│   Server        │
│  (server.js)    │
└────────┬────────┘
         │
         ▼
┌─────────────────┐        ┌──────────────────────┐
│ prompts-data    │  ────▶ │ services/prompts.js  │
│    .json        │ fallback│ (default prompts)    │
│ (actual data)   │        └──────────────────────┘
└─────────────────┘
```

### API Endpoints

**GET /api/prompts**
```
Описание: Получить текущие промпты
Требования: X-API-Key header
Ответ:
{
  "prompts": {
    "food": "...",
    "nonfood": "...",
    "inter": "...",
    "ge": "..."
  },
  "etag": "abc123...",
  "lastModified": "2025-02-05T12:00:00.000Z"
}
```

**POST /api/prompts**
```
Описание: Обновить промпты
Требования:
  - X-API-Key header
  - Body: { "prompts": {...}, "etag": "abc123..." }
Ответ (успех):
{
  "success": true,
  "message": "Промпты успешно обновлены",
  "etag": "def456...",
  "lastModified": "2025-02-05T12:05:00.000Z"
}

Ответ (конфликт):
{
  "error": "Конфликт: Промпты были изменены другим пользователем",
  "message": "Пожалуйста, обновите страницу и повторите редактирование",
  "currentETag": "xyz789...",
  "currentPrompts": {...},
  "lastModified": "2025-02-05T12:04:00.000Z"
}
```
